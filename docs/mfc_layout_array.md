**최신 결과는 5절의 `rack_scaled_layout.png`·`ambient_scaled_layout.png`다.**
6절에서는 동일한 배열로 냉동 A의 `frozen_scaled_layout.png`와

  A 존의 렉은 `A`, B 존의 렉은 `B`로 표시한다. 상온의 존 미지정 렉은 `R`을 사용한다.
- `walkable_masks`: `.`인 칸만 이동 가능한 통로·교차로로 표시한다. `#`은 통행을 막는
  기둥이며 `?`·`U`는 이동 가능한 칸에 포함하지 않는다. 경로 계산은 수행하지 않는다.
- `RACK_LABELS`: 번호를 확인한 렉만 도면의 `(행, 열)`과 `A01-01` 같은 코드로 연결한다.
  현재 개별 번호는 미확인이므로 비워 두었다. 층·선반 코드는 입력하지 않는다.
- `rack_positions`: 확인된 라벨만 `[존, 복도, 렉, 도면, 행, 열]`로 만든 배열이다.
  라벨이 없으면 `(0, 6)` 크기의 빈 배열이다.
- 위 변수들은 1~4절의 원본 배치 초안이다. 5절의 `scaled_cells`·`scaled_layout_arrays`에
  출고 렉 코드와 연결한 칸을 별도로 생성한다. 아래 스케일 조정 설명을 따른다.

구역별 좌표는 서로 독립적이며, 스케일 지도 칸의 너비·높이는 일정하지 않다.

기존 사진의 C·D 표기는 배열에 보존하고 추가 렉은 존 미지정 `R`로 표현한다.
이전에 상온을 30×34로 확장한 뒤 사용자가 편집한 현재 `GRID_TEXT`를 기준으로 삼는다.

사진의 굽은 외곽은 계단 모양으로 근사한다.
구역 전체 그림에 더해 `reports/mfc_layout/ambient_layout.png`에 상온 확대 그림을 저장한다.

## 저장된 레이아웃 구조 (다른 노트북용)

레이아웃은 시기별로 조금씩 바뀌었으므로 **버전별 JSON 스냅샷**으로 저장한다.
현재 버전은 `2026-09`(9월 출고 렉 기준)이며 08 노트북 5절을 실행하면
`references/mfc_layout/layout_2026-09.json`을 다시 쓴다.

```python
from hit_stocks_analysis.mfc_layout import load_layout

layout = load_layout("2026-09")
layout.grids["C_D"]   # 도면별 문자 격자 (. 통로, # 기둥, A·B·C·D·R 렉 영역)
layout.racks          # rack_code 인덱스, 렉 칸 한 행 = 한 렉
layout.rules          # 존별 복도 순서·번호 증가 방향·위/아래 면 홀짝, 예외, 복도별 면 행
layout.unplaced       # 지도 위치 미확인 렉 (B08-00, C08-00)
```

- `racks` 열: `area`, `zone`, `aisle`, `rack`, `symbol`, `observed`, `x`, `y`, `width`,
  `height`, `placement`, `cx`, `cy`. `cx`·`cy`는 칸 중심이며 방문 렉을 점으로 찍을 위치다.
  작업자가 서는 통로상의 피킹 좌표는 아니다.
- `observed=False`는 같은 면의 관측 번호 사이의 `~` 자리다. 실제 렉 여부는 미확인이다.
- 좌표는 도면(`A`, `B`, `C_D`)별 독립 상대 좌표다. 다른 도면의 좌표를 같은 축에 두지 않는다.
- 렉 목록은 9월 출고에서 관측한 코드다. 다른 시기 주문의 렉이 테이블에 없을 수 있으므로
  연결되지 않은 코드는 따로 집계한다.
- 원본은 `src/hit_stocks_analysis/mfc_layout.py`의 `GRID_TEXT`(격자)와 `ZONE_RULES`
  (규칙)다. 격자 수정은 노트북이 아니라 이 모듈에서 하고, 노트북을 다시 실행해 저장한다.
  `REVERSE_NUMBERING`·`UPPER_ODD`는 `ZONE_RULES`에서 파생하며, 저장 시
  `FACE_ROWS`의 복도 배치가 규칙의 복도 순서와 맞는지 검사한다.
- 과거 레이아웃은 규칙·격자를 확인한 뒤 별도 버전 파일로 추가한다. 현재 버전을 덮어써
  과거 자료에 적용하지 않는다.

주문별 피킹 렉 표시는 [09_order_picks_on_layout.ipynb](../notebooks/09_order_picks_on_layout.ipynb)에 있다.
2026-08-10~09-27 출고만 사용한다. 그 이전 기간은 코드 체계가 달라 이 버전에 찍지 않는다.

## 사용자 확인 조건

- 최신 스케일 목표는 **알파벳 한 칸 = 렉 코드 하나**다. 현재 사진 기반 초안의 칸 수를
  그대로 렉 수로 확정하지 않고, 2026년 9월 출고의 존·복도·렉 목록과 대조해 조정한다.
- A·B는 복도 아래쪽이 홀수, 위쪽이 짝수다. 상온 C·D는 반대로 아래쪽이 짝수,
  위쪽이 홀수다. 렉 번호는 A·B에서 왼쪽→오른쪽,
  C·D에서 오른쪽→왼쪽으로 증가한다. B·C·D는 사용자의 최종 정정 방향을 적용한다.
- A01~11, B00~08, C00~08은 아래→위로, D00~08은 위→아래로 배치한다.
  B09는 오른쪽 입구 근처에서 위→아래로 01~06이며 A12는 오른쪽 위 `##A`의 A다.
- 현재 A·B·C·D 기준으로 표현한다.
  A는 냉동, B는 냉장, C는 상온 히트맵, D는 상온 랜덤 진열이다.
- 로케이션의 존·복도 번호·렉 번호까지만 유지하고 층·선반은 제외한다.
  예: `A01-01-105`와 `A01-01-205`는 같은 `A01-01`로 묶는다.
- 이동 거리는 실제 미터가 아닌 **상대적인 칸 수**로 표현한다.
- 복잡한 그래프 기반 계산 대신 배열과 단순한 로케이션 계산을 사용한다.
- 패킹 구역은 냉장과 상온 사이이며, 경로에는 패킹 구역으로의 복귀를 포함한다.
- 기존의 분석 보류 요청에서 이번에 추가된 범위는 레이아웃 표현과 이를 기반으로 한
  단순 동선 계산 준비다. 입출고 전체 집계나 압축진열 효과 검증을 시작하는 요청은 아니다.

## 배열 설계안

랙별로 아래 열을 갖는 2차원 배열을 제안한다. 이 형식은 설계안이며 실제 좌표는 미입력이다.

```python
# 한 행 = 존, 복도 번호, 렉 번호, 피킹 지점의 행 좌표, 피킹 지점의 열 좌표
rack_positions = [
    # ["A", "01", "01", row, col],
    # 확인된 현재 번호와 위치를 입력한다.
]

# 공통 패킹 구역의 대표 출발·복귀 위치: 좌표 확인 후 입력
packing_position = None
```

- 배열의 행·열 좌표와 복도·렉 번호는 별개다. 번호를 그대로 좌표로 사용하지 않는다.
- 좌표는 렉 내부가 아니라 해당 렉 앞에서 작업자가 서는 통로상의 대표 피킹 위치를 뜻한다.
- 층·선반 차이에 따른 수직 이동·작업 시간은 이 모델에서 계산하지 않는다.
- 원본 로케이션은 별도로 유지하며 계산에만 렉 단위 키를 사용한다.
- 패킹 구역을 한 대표점으로 둘 경우 실제 여러 패킹대의 차이를 생략하는 근사임을 표시한다.

## 단순 거리 계산안

확인된 통로를 따라 이동할 순서를 좌표 배열로 정한다.
패킹 위치에서 출발해 피킹 지점과 필요한 복도 끝의 경유점을 방문한 뒤 패킹 위치로 돌아온다.

```python
# route에는 복도 연결을 반영한 경유점과 마지막 패킹 복귀점까지 포함한다.
distance = sum(
    abs(next_row - row) + abs(next_col - col)
    for (row, col), (next_row, next_col) in zip(route, route[1:])
)
```

- 위 식은 이미 정한 경로의 칸 수를 합산한다. 최단 경로를 자동으로 찾는 식이 아니다.
- 렉이나 기둥을 가로질러 갈 수 없는 구간은 복도 끝 등 통행 가능한 경유점을 명시한다.
  두 로케이션 좌표 차이만으로 모든 구간의 이동 거리를 계산하지 않는다.
- S-Shape의 통로 순서·방향은 배치와 연결 규칙이 확인된 뒤 정한다.
  임의의 복도 연결이나 번호 정렬을 실제 경로로 사용하지 않는다.
- 결과의 단위는 비교용 상대 칸 수이며 미터·시간으로 환산하지 않는다.

## 실제 좌표 입력 전에 남은 확인

- 복도 번호 방향·렉 번호 증가 방향·양쪽 홀짝은 위 조건으로 확인되었다.
  기존 배열의 `.`은 모두 통로·교차로이고 `#`은 기둥이라는 답변을 받았다.
  스케일 조정 시 이 배치를 기준으로 삼는다. B08-00은 B08-02 바로 왼쪽으로 반영했고 C08-00의 위치는 답변 대기다.
- 전체 사진의 작은 렉 번호는 정확히 읽기 어렵다. 개략도의 I·W·옛 A는 현재 번호와의
  대응을 확인하기 전까지 현재 배열에 옮기지 않는다.
- C 뒤로 D가 길게 이어지는 상대 배치는 확인되었다. 각 구역 출입 연결, 패킹 대표점,
  상대적인 통로 간격의 정확한 값은 아직 미확정이다.
  사진으로 확인되지 않는 위치를 채워 넣어 완성된 센터 배열이라고 제시하지 않는다.

현재는 사진 기반 초안과 렉 코드별 스케일 지도를 생성한다. 개별 렉의 실제 경계·피킹 좌표는
추가 정보 확인 후 확정한다. 위 거리 계산안은 향후 설계 설명일 뿐 구현하지 않았다.

## 렉 단위 스케일 조정 결과와 근사

- 2026년 9월 1~27일 출고에서 A·B·C·D 렉 402개를 관측했다. 401개를 칸과 1:1로
  연결하고, 위치 미확인인 C08-00을 `unplaced_racks.csv`로 분리했다.
  B08-00은 B08-02 바로 왼쪽(`CONFIRMED_ZERO_RACKS`)에 둔다.
- D07-01은 9월 출고에 없고 현재 철거된 렉이다. 과거 출고 표시를 위해 `ASSUMED_RACKS`로
  추가했으며 `placement`가 `assumed_removed`다. 추가 후 D07 위쪽 면 배분이 바뀌었다(Q26).
- `src/hit_stocks_analysis/mfc_layout.py`의 `FACE_ROWS`는 기존 배치의 행과 복도 진열면을
  연결한다. A 20행·B 23행은 두 복도의 맞닿은 면을 한 행에 표현한 것으로 **근사**하여
  높이를 반씩 나눈다. 이 대응은 추가 확인 시 수정한다.
- 각 면의 관측 최소~최대 번호 사이를 홀짝 간격으로 나눈다. 같은 면 사이의 미관측
  번호 14개는 `~`로 남기며, 실제 렉·통로·기둥 중 무엇인지 임의로 정하지 않는다.
  관측 최소·최대 바깥의 번호는 추가하지 않는다.
- 기존 연속 렉 구간의 길이 비율에 맞춰 코드 자리를 배분하고, 해당 영역 안을 칸으로
  나눈다. **구간별 번호 경계·칸 너비는 비례 근사다. 실제 렉 좌표로 확정된 것이 아니다.**
  통로 `.`과 기둥 `#`은 그대로 두며, 칸이 해당 영역을 덮지 않는 것을 검증했다.
- 원본 렉 영역 중 코드가 배정되지 않은 부분은 옅은 회색으로 남긴다. 미배정 영역을
  통로로 바꾸거나 출고 코드만으로 렉 부재를 판단하지 않는다.
- 히트맵은 보류한다. 알파벳과 번호는 로케이션 식별용이며 출고량을 표시하지 않는다.

`scaled_layout_arrays[area]`는 `[기호, 렉 코드, x, y, 너비, 높이]`를 열로 갖는 2차원 배열이다.
각 행은 칸 하나이고, `~`를 제외하면 관측 렉 하나와 대응한다. 좌표는 기존 배치의 상대 좌표다.
균일 크기의 문자 격자가 아니므로 배열의 행 번호 차이를 이동거리로 사용하지 않는다.
`scaled_rack_cells.csv`에는 존·복도·렉, 관측 여부와 배치 방법도 함께 저장한다.
`scaled_layout_arrays.npz`는 배열을 문자열로 저장하므로 좌표 계산 시 해당 열을 수치로 변환한다.

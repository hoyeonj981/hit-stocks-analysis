# MFC 입출고 분석 계획안

작성일: 2026-10-14

사용자가 분석 방법을 물어본 데 대한 **제안**이다. 실행 결과나 확정된 지표가 아니며,
데이터 집계·동선 계산은 아직 시작하지 않는다.
운영 사실은 [MFC 운영 조건과 분석 전제](mfc_operating_context.md)를 따른다.

## 목적과 데이터 역할

- 출고: 어떤 상품이 얼마나 많은 장바구니에 포함되고, 어느 위치들을 방문하도록 할당되는지 파악한다.
- 입고: 그 상품을 얼마나 자주, 한 번에 얼마나 많이 받는지와 소비기한별 유입을 파악한다.
- 개선안 검토: 동일 SKU의 통합 진열, 히트 구간 배치, 유사 상품 인접 위험을 함께 검토한다.
  공간 절감·실제 작업시간 단축·오피킹 감소는 현재 CSV만으로 실증할 수 없다.

## 1. 집계 기준과 로케이션 이력 점검

- 출고 기본 대상은 `SHIPPED`, 양의 `pickingQuantity`다. 주문번호·SKU·로케이션·요청일·
  소비기한을 보존한다. 주문의 분할 행은 SKU별 주문 건수에서 중복 계산하지 않고 수량은 합산한다.
- 입고는 양의 `receivingQuantity`를 합산하고 `inventoryTransferOrderId`를 입고 주문 식별자로
  사용한다. 유통기한별 분할 행을 ID만으로 제거하지 않는다.
- 실제 방문 위치와 데이터에 할당된 위치는 구분한다. 결측·특수 로케이션은 따로 집계하고,
  해석할 수 없는 코드를 임의 좌표에 배치하지 않는다.
- I·W가 현재 A로 바뀌었다는 사실만으로 문자열을 치환하지 않는다.
  예를 들어 옛 I01·W01·A01이 같은 현재 A01이라고 단정할 수 없다.
  변경 시점과 전체 코드 대응표가 확보되기 전에는 원본 코드와 기간을 보존한다.
- 입고 예정일과 출고 요청일이라는 날짜 의미를 표시한다. 입출고를 비교할 때는 공통 자료
  기간·날짜를 사용한다. 현재 2025년 출고 8월 31일 결측, 2026년 자료 종료일 차이를 반영한다.
- 연도·월별 변화와 최근의 완전한 주·월을 구분한다. 장기 누적 위치 수를 현재 동시 분산으로
  해석하지 않으며, 관측 기간·주문 건수도 함께 표시한다.

## 2. 출고: SKU 분산과 장바구니의 위치 분산

| 관점 | 우선 볼 항목 | 해석 |
| --- | --- | --- |
| 상품 수요 | 출고 수량, 고유 주문 건수, 전체 주문 중 포함 비율 | 보충 물량과 장바구니 등장 빈도를 구분 |
| SKU 위치 분산 | 일·주·월별 할당 로케이션·복도·렉 수 | 해당 기간 출고에서 관측된 분산, 동시 재고 점유는 아님 |
| 위치 집중도 | 가장 많이 할당된 위치의 비중, 출고량 80%를 담당한 위치 수 | 여러 위치가 관측돼도 주로 한 위치만 쓰는지 구분 |
| 한 주문 내 분산 | 주문·SKU별 복수 로케이션 할당 비율 | 한 주문의 같은 SKU가 여러 위치에 걸쳐 있는 경우 파악 |
| 장바구니 위치 | 주문별 SKU·존·복도·렉·로케이션 수 | SKU 하나의 분산과 주문 전체의 분산을 구분 |
| 소비기한별 위치 | SKU·소비기한별 위치와 수량 | 다른 소비기한에 의한 분산과 같은 소비기한의 분산을 구분 |

위치 비중은 수량 기준과 주문-위치 할당 건수 기준을 명시적으로 구분한다.
기간 중 소비기한별 위치 기록만으로 현재 혼적 상태나 선입선출 준수 여부를 확정하지 않는다.

## 3. 입고: 통합 진열 후보의 보충 특성

- SKU별 일·주·월 입고량, 입고 예정일 수, 고유 입고 주문 수를 산출한다.
- 입고 주문·SKU 단위로 분할 행을 합쳐 1회 입고량과 날짜별 최대 유입량을 확인한다.
  입고 주문 건수를 진열 작업 횟수나 차량 도착 횟수로 바꾸어 부르지 않는다.
- 소비기한별 유입 수량과 종류를 보되, 동시에 보관 중인 소비기한 종류 수라고 해석하지 않는다.
- 같은 기간의 출고량·주문 빈도·분산 지표를 SKU 단위로 연결해 통합 진열 검토 후보를 만든다.
  초기에는 원자료 지표를 나란히 보고 임의 가중치의 단일 점수를 만들지 않는다.
- 입고량에서 출고량을 뺀 값은 흐름 차이일 뿐 현재 재고·폐기량·공간 점유가 아니다.
  공간 적합성 판단에는 재고 스냅샷, 상품·포장 치수, 로케이션 수용량이 추가로 필요하다.
- `displayLocationCode`가 입고 당시 진열 위치인지 등 의미를 확인하기 전에는 출고 위치와
  연결해 진열 이동 이력을 재구성하지 않는다.

## 4. 도면·용량 정보 확보 후: 복귀 동선과 배치 시나리오

- 실제 통로 연결, 기둥, 출입구, 패킹 구역, 거리, 선반 높이와 코드 대응을 확인한다.
  로케이션 번호 차이나 이미지 픽셀 차이를 실제 거리로 사용하지 않는다.
- 동일한 과거 장바구니를 대상으로 현재 배치와 대안 배치를 비교한다.
  출발 → 필요한 위치 방문 → 패킹 구역 복귀를 포함하고 경로는 S-Shape 가정을 명시한다.
- 평균뿐 아니라 긴 경로가 발생하는 주문의 비율·상위 구간도 본다.
  원거리 위치에 있는 한두 상품 때문에 추가되는 구간은 주문 전체 경로를 다시 계산해 비교한다.
  가장 먼 위치까지 거리의 두 배만으로 S-Shape 전체 경로를 대체하지 않는다.
- 히트 구간 평가에는 상품별 수량 외에 **장바구니 전체가 히트 구간에 포함되는 주문 비율**,
  히트 구간 밖의 위치가 필요한 주문 비율을 본다. 온도대별 배치 가능 범위도 반영한다.
- 배치안은 온도대, 가용 재고·소비기한, 공간 수용량, 선반 높이·작업 제약을 충족하는
  시나리오로 제한한다. 정보가 없으면 가정과 미검증 조건을 표시한다.
- 기간 앞부분으로 후보를 정하고 이후 기간의 장바구니로 평가한다. 같은 기간에 맞춘
  개선 효과를 미래 성능으로 단정하지 않는다.
- 결과는 **할당 위치와 경로 가정에 따른 추정치**다. 실제 작업시간·8분 목표 준수율은
  작업 로그나 현장 검증 없이는 계산하지 않는다.

## 5. 유사 상품 인접 진열과 결과물

- 상품명·브랜드·규격 차이로 검토할 유사 상품 쌍을 제안하고 사람이 확인한다.
  외형 유사성은 상품 이미지·현물 정보가 필요하다.
- 현재 진열 정보와 도면이 확보되면 같은 렉·인접 선반 등 확인된 관계로 근접 배치를 본다.
  과거 서로 다른 시점에 사용한 위치를 동시 인접 진열로 간주하지 않는다.
- 실제 오피킹 이력 없이 오류 확률을 산출하지 않고 **인접 진열 검토 후보**로 제시한다.
- 첫 결과물은 ① SKU 수요·분산표 ② 장바구니별 위치 분산표 ③ 입고·보충 특성표와
  이를 연결한 압축진열 검토 후보 목록을 권한다. 도면·현재 재고 확보 후 공간 검토로 확장한다.
- 초기에는 관리자 검토용 배치 후보를 제공한다. 자동 갱신·현장 적용은 별도 범위로 둔다.
